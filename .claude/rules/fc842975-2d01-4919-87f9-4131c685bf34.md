<rule_activation id="fc842975-2d01-4919-87f9-4131c685bf34" title="Standardize Structured Logging with Contextual Metadata: Components Use Structured" applies_to="**/*.{ts,js}">
These rules are ALWAYS ACTIVE for all TypeScript and JavaScript files.

**In scope:**
- All TypeScript/JavaScript modules in apps/cli/src/**
- All agent packages in packages/agent/src/**
- Command handlers and utility functions that perform I/O operations
- Client libraries that interact with external services
- Test runners and development utilities

**Out of scope:**
- Third-party library internal logging (unless configurable)
- Build scripts and tooling configuration files
- Static content and documentation files
- Test fixtures and mock data

**Exceptions:**
- EXC-001: Legacy code in maintenance mode that is scheduled for deprecation within 6 months
- EXC-002: Performance-critical hot paths where structured logging overhead is measurably prohibitive
</rule_activation>

### Rules

- **R-LOG-001** MUST: All components MUST use a structured logging framework that supports contextual metadata and consistent formatting.
- **R-LOG-002** MUST: Production code MUST NOT use console.log or console.error directly; use the structured logger instead (test files excluded).
- **R-LOG-003** SHOULD: Components SHOULD use a centralized logger utility module (e.g., utils/logger.ts) with consistent configuration.
- **R-LOG-004** SHOULD: Log messages SHOULD include standard metadata fields (timestamp, severity, component, correlationId, userId) where applicable.
- **R-LOG-005** SHOULD: Log levels SHOULD be configurable via environment variables to enable different verbosity in development vs production.
- **R-LOG-006** MUST: Sensitive information (API keys, tokens, PII) MUST NOT be logged without redaction.

### Verify

```bash
# Count direct console usage in production code (should be minimal or zero)
grep -r "console\.log\|console\.error" apps/cli/src packages/agent/src --include="*.ts" --exclude="*.test.ts" | wc -l

# Count structured logging usage (should significantly exceed console usage)
grep -r "logger\.info\|logger\.error\|logger\.warn\|logger\.debug" apps/cli/src packages/agent/src --include="*.ts" | wc -l

# Verify logger utility modules exist
find apps/cli/src packages/agent/src -name "logger.ts" -o -name "*logger*.ts" | head -5
```

**Accept when:**
- Structured logging framework usage (logger.info/error/warn/debug) significantly exceeds direct console usage in production code
- Logger utility modules exist and are imported by components in the detected pattern files (apps/cli/src/utils/logger.ts, etc.)
- Code review checklist includes verification of appropriate log levels and context inclusion for new logging statements
- Automated linting rules flag direct console.log usage in production code paths

<enforcement>
Claude Code MUST verify compliance with structured logging standards before completing logging-related tasks. Direct console.log usage in production code requires explicit justification and exception approval. All new logging statements MUST use the structured logger with appropriate context and severity levels.
</enforcement>
