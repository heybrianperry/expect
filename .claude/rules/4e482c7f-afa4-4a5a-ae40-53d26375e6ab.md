<rule_activation id="4e482c7f-afa4-4a5a-ae40-53d26375e6ab" title="Adopt Browser-Based End-to-End Testing for CI/CD Pipelines" applies_to="**/*">
These rules are ALWAYS ACTIVE for browser packages and CI/CD pipeline configurations.
</rule_activation>

### Rules

- **R-E2E-001** MUST: Browser packages MUST include end-to-end tests that execute in real or headless browser environments as part of the CI/CD pipeline.
- **R-E2E-002** MUST: E2E tests MUST cover critical user interaction patterns including DOM manipulation, event handling, and state changes.
- **R-E2E-003** MUST: Cookie handling and injection mechanisms MUST be validated through dedicated E2E test suites.
- **R-E2E-004** SHOULD: Visual regression testing through snapshot comparisons SHOULD be implemented for UI-critical components.
- **R-E2E-005** SHOULD: E2E tests SHOULD be organized by functional area (e.g., act.test.ts for interactions, cookie-injection.test.ts for cookie handling).
- **R-E2E-006** MUST: E2E test failures MUST block deployment in CI/CD pipelines.
- **R-E2E-007** MAY: Teams MAY use browser automation frameworks such as Playwright, Puppeteer, or Selenium based on project requirements.

### Verify

```bash
# Check for E2E test files organized by functional area
find packages/*/tests -name '*.test.ts' -type f | grep -E '(act|cookie|snapshot)' | wc -l

# Verify browser automation framework dependencies
grep -r 'browser' package.json | grep -E '(playwright|puppeteer|selenium)'

# Check CI/CD pipeline includes E2E test execution
grep -r 'test.*e2e\|e2e.*test' .github/workflows/*.yml || grep -r 'test' .github/workflows/*.yml
```

**Accept when:**
- Browser packages contain dedicated E2E test files organized by functional area (act, cookie-injection, snapshot)
- CI/CD pipeline configuration includes browser E2E test execution with failure blocking deployment
- Browser automation framework dependencies are present in package.json and tests execute in headless browser environments

<enforcement>
Claude Code MUST NOT skip or defer verification. E2E tests are verified by automated CI/CD pipeline checks, code review process, and periodic test coverage audits. Pull requests without E2E tests for browser functionality changes are blocked from merging.
</enforcement>
