<rule_activation id="dd25c3e9-f798-45eb-ad55-38cfe6f05f63" title="Standardize Test File Organization in Dedicated Tests Directories" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the repository to ensure consistent test file organization across packages and applications.
</rule_activation>

### Rules

- **R-TEST-001** MUST: All test files MUST be placed in a dedicated 'tests' directory at the package or application root level.
- **R-TEST-002** MUST: Test file names MUST follow the pattern '*.test.ts' or '*.test.js' to enable consistent test discovery.
- **R-TEST-003** SHOULD: Test directories SHOULD mirror the structure of the source code they test for maintainability.
- **R-TEST-004** MUST: CI/CD pipeline configurations MUST reference the standardized 'tests' directory pattern for test execution.
- **R-TEST-005** SHOULD: Test utilities and fixtures SHOULD be organized in subdirectories within the tests directory (e.g., 'tests/fixtures', 'tests/helpers').
- **R-TEST-006** MUST_NOT: Test files MUST NOT be co-located with source files in the same directory unless explicitly justified and documented.

### Scope

**In scope:**
- All packages within the monorepo (packages/*)
- All applications within the monorepo (apps/*)
- Unit tests, integration tests, and end-to-end tests
- Test utilities, fixtures, and helper functions
- CI/CD pipeline test execution stages

**Out of scope:**
- Documentation examples that are not executed as tests
- Build scripts and tooling configuration files
- Third-party dependencies and node_modules
- Generated code or artifacts in dist/build directories

**Exceptions:**
- EXC-001: Legacy packages undergoing migration may temporarily maintain alternative test structures

### Verify

```bash
# Check for test files outside tests directory
find . -name '*.test.ts' -o -name '*.test.js' | grep -v node_modules | grep -v '/tests/' && echo 'FAIL: Test files found outside tests directory' || echo 'PASS'

# Verify standard test directories exist
test -d apps/cli/tests && test -d packages/browser/tests && test -d packages/cookies/tests && echo 'PASS: Standard test directories exist' || echo 'FAIL'

# Check test runner configurations reference tests directory
grep -r "testMatch\|testRegex" package.json tsconfig.json jest.config.* vitest.config.* 2>/dev/null | grep -q 'tests/.*\.test' && echo 'PASS: Test configs reference tests directory' || echo 'WARN'
```

**Accept when:**
- All test files with .test.ts or .test.js extensions are located within a 'tests' directory at the package or app level
- CI/CD pipeline configurations successfully discover and execute tests using the standardized directory pattern
- Build outputs (dist, build directories) do not contain any files from tests directories
- New packages created from templates automatically include the standard tests directory structure

<enforcement>
Claude Code MUST NOT skip or defer verification of test file organization. When creating or modifying test files, verification commands MUST be executed to ensure compliance with the standardized directory structure. CI/CD pipeline failures due to non-compliant test locations MUST be addressed before proceeding.
</enforcement>
