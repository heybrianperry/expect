<rule_activation id="d12a6bcc-6274-463e-8d3b-de30a16ecd8e" title="Adopt Browser-Based Rendering with rrweb for E2E Testing and Demo Recording" applies_to="**/*">
These rules apply to E2E testing and demo recording implementations where browser rendering is required.
</rule_activation>

### Rules

- **R-BR-001** MUST: E2E testing and demo recording implementations MUST use browser-based rendering with rrweb or equivalent DOM replay technology for capturing user interactions.
- **R-BR-002** MUST: Browser rendering utilities MUST provide locator resolution capabilities to accurately identify and interact with DOM elements during replay.
- **R-BR-003** MUST: Recording scripts MUST capture sufficient DOM state and mutation information to enable faithful replay of user sessions.
- **R-BR-004** SHOULD: Demo recording implementations SHOULD separate recording logic from replay logic to enable independent testing and optimization.
- **R-BR-005** SHOULD: Browser rendering modules SHOULD provide utilities for resolving locators across different selector strategies (CSS, XPath, text content).
- **R-BR-006** MAY: Implementations MAY extend rrweb with custom event types or plugins to capture application-specific interactions.

### Verify

\`\`\`bash
# Verify rrweb is present in the codebase
grep -r "rrweb" packages/browser/src/ apps/website/scripts/ --include="*.ts" --include="*.js"

# Verify recording and replay utilities exist
grep -r "record.*demo\|rrvideo\|resolve-locator" packages/browser/src/ apps/website/scripts/ --include="*.ts"

# Verify rrweb dependency
npm list rrweb || yarn list --pattern rrweb
\`\`\`

**Accept when:**
- rrweb or equivalent DOM replay library is present in project dependencies
- At least one recording script and one replay utility exist in the codebase
- Locator resolution utilities are implemented with support for multiple selector strategies
- E2E tests or demo scripts successfully use browser-based rendering for interaction capture
