These rules are ALWAYS ACTIVE for all TypeScript test file creation and organization within the codebase.
</rule_activation>

### Rules

- **R-TS-TEST-001** MUST: All TypeScript test files MUST use the .test.ts file extension
- **R-TS-TEST-002** MUST: Test files MUST be placed in a tests/ directory at the appropriate package or application level
- **R-TS-TEST-003** SHOULD: Test file names SHOULD reflect the module or feature being tested (e.g., agent.test.ts for agent functionality)
- **R-TS-TEST-004** MUST_NOT: Test files MUST NOT use alternative extensions such as .spec.ts, .test.js, or _test.ts
- **R-TS-TEST-005** SHOULD: Each package or application SHOULD maintain its own tests/ directory for test isolation
- **R-TS-TEST-006** MAY: Placeholder test files (e.g., placeholder.test.ts) MAY be used temporarily during initial project setup

**In scope:**
- All TypeScript test files across all packages and applications
- Unit tests, integration tests, and end-to-end tests written in TypeScript
- Test files for CLI applications, browser packages, and agent packages
- New test files created during development

**Out of scope:**
- JavaScript test files in legacy codebases (if any)
- Test files in non-TypeScript languages
- Documentation or example files that are not executable tests
- Third-party test files in node_modules

**Exceptions:**
- EXC-001: Migrating from a legacy codebase that uses .spec.ts convention
- EXC-002: Third-party framework explicitly requires different naming convention

### Verify

```bash
# Count TypeScript test files with .test.ts extension
find . -type f -name '*.test.ts' | wc -l

# Check for non-compliant test file extensions (should return 0)
find . -type f \( -name '*.spec.ts' -o -name '*_test.ts' \) -not -path '*/node_modules/*' | wc -l

# Verify test runner configuration includes .test.ts pattern
grep -r 'testMatch.*\.test\.ts' --include='*.config.*' --include='package.json'
```

**Accept when:**
- All TypeScript test files use .test.ts extension (first command returns count > 0, second command returns 0)
- No test files exist with alternative extensions like .spec.ts or _test.ts outside of node_modules
- Test runner configuration explicitly includes .test.ts pattern in testMatch or equivalent setting
- CI/CD pipeline successfully discovers and executes all test files using .test.ts glob pattern

<enforcement>
Claude Code MUST NOT skip or defer verification. All test files created must adhere to the .test.ts naming convention and be placed in tests/ directories. Automated CI/CD checks, ESLint rules, and code review processes enforce compliance.
</enforcement>
