<rule_activation id="3beed4e3-e5ac-4876-b454-f2e79fc33623" title="Standardize Core Utility Libraries for CLI and Browser Packages" applies_to="**/*">
These rules are ALWAYS ACTIVE for organizing utility functions and shared libraries across CLI applications and browser packages.
</rule_activation>

### Rules

- **R-CUL-001** MUST: All utility functions MUST be organized into dedicated modules within a utils/ directory structure.
- **R-CUL-002** MUST: Shared utilities used across multiple packages MUST be extracted into the packages/ directory as reusable modules.
- **R-CUL-003** MUST: Each utility module MUST have a single, well-defined responsibility (e.g., formatting, clipboard operations, image processing).
- **R-CUL-004** SHOULD: State management utilities SHOULD be organized in a separate stores/ directory when using state management patterns.
- **R-CUL-005** SHOULD: Utility modules SHOULD export pure functions without side effects where possible to improve testability.
- **R-CUL-006** MUST NOT: Utility modules MUST NOT contain business logic specific to individual features; they must remain generic and reusable.
- **R-CUL-007** MAY: Application-specific utilities MAY remain in the application's utils/ directory if they are not needed by other packages.

### Verify

```bash
# Check that utility files exist in expected locations
find apps/cli/src/utils -type f -name '*.ts' | wc -l | grep -E '[0-9]+'

# Verify utilities export functions properly
grep -r 'export.*function' apps/cli/src/utils/ packages/*/src/ | grep -v 'node_modules'

# List shared utility packages
find packages/*/src -type f -name '*.ts' | head -5
```

**Accept when:**
- Utility functions are organized in dedicated utils/ directories within applications
- Shared utilities exist in packages/ directory and are imported by multiple applications
- Each utility module has a clear, single responsibility reflected in its filename
- No business logic specific to individual features exists in utility modules

<enforcement>
Claude Code MUST NOT skip or defer verification. Code review process must check for proper utility organization and single responsibility. Automated linting rules must detect circular dependencies and improper imports.
</enforcement>
