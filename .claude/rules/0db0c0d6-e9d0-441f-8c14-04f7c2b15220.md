<rule_activation id="0db0c0d6-e9d0-441f-8c14-04f7c2b15220" title="Standardize Public API Error Handling and Event Contracts" applies_to="**/*">
These rules are ALWAYS ACTIVE for all public-facing API modules, external integration points, and client-facing SDK components. This applies to error handling, event contracts, and constant definitions exposed to external consumers.
</rule_activation>

### Rules

- **R-API-001** MUST: All public-facing API modules MUST define their error contracts in dedicated error definition files (e.g., errors.ts) that export typed error classes or error code constants.
- **R-API-002** MUST: Public API constants that form part of the external contract MUST be defined in dedicated constants files (e.g., constants.ts) separate from implementation logic.
- **R-API-003** MUST: Event schemas for public APIs MUST be defined in dedicated event definition files (e.g., viewer-events.ts) with explicit type definitions for all event payloads.
- **R-API-004** MUST: Error definitions MUST include machine-readable error codes or types that remain stable across versions to enable programmatic error handling by consumers.
- **R-API-005** SHOULD: Public API contracts SHOULD be versioned and changes to error codes, constants, or event schemas SHOULD follow semantic versioning principles.
- **R-API-006** SHOULD: Contract definition files SHOULD be co-located with their respective package modules (e.g., packages/browser/src/*/errors.ts) to maintain clear ownership.
- **R-API-007** MUST NOT: Public API contract definitions MUST NOT contain implementation logic or business rules; they MUST only define the interface contract.
- **R-API-008** MAY: Packages MAY provide utility functions for extracting or transforming contract artifacts (e.g., extract-close-artifacts.ts) as long as the core contracts remain stable.

### Verify

```bash
# Check for contract definition files in public-facing packages
find . -path '*/src/*/errors.ts' -o -path '*/src/*/constants.ts' -o -path '*/src/*-events.ts' | grep -E '(packages|apps)' | wc -l

# Verify error exports in contract files
grep -r 'export.*Error' --include='errors.ts' packages/ apps/ | head -5

# Verify constant exports in contract files
grep -r 'export const' --include='constants.ts' packages/ apps/ | head -5
```

**Accept when:**
- Each public-facing package contains at least one contract definition file (errors.ts, constants.ts, or events.ts) in its source tree
- Contract files export only type definitions, interfaces, constants, or error classes without implementation logic
- Error definitions include stable identifiers (error codes or discriminated type fields) that enable programmatic handling
- Contract files are referenced in package documentation or API reference materials

<enforcement>
Claude Code MUST NOT skip or defer verification. All changes to public-facing API modules must be verified against these contract requirements through automated linting rules, code review checklists, and CI pipeline checks for breaking changes.
</enforcement>
