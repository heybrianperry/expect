<rule_activation id="0894403e-bd1b-4931-98f7-6a23a3159bca" title="Standardize React Hooks for UI State Management in CLI Components: Screen Components Minimize" applies_to="apps/cli/src/**/*">
These rules are ALWAYS ACTIVE for all files matching `apps/cli/src/**/*`.

Screen components in the CLI application must use React hooks for state management, minimizing direct state manipulation and delegating complex logic to custom hooks or utility functions.

**Scope:**
- All React-based CLI screen components in apps/cli/src/components/screens/
- Custom hooks in apps/cli/src/hooks/
- Interactive terminal UI components requiring state management
- Components handling user input, async operations, or multi-step workflows

**Out of scope:**
- Non-React CLI utilities and pure functions
- Backend services or API handlers
- Static configuration files
- Build scripts and tooling configuration

**Exception:** EXC-001: Integrating with third-party libraries that require class components or legacy patterns
</rule_activation>

### Rules

- **R-HOOKS-001** SHOULD: Screen components SHOULD minimize direct state manipulation and delegate complex logic to custom hooks or utility functions.

### Verify

```bash
# Verify no class-based components in screen directories
grep -r 'class.*extends.*Component' apps/cli/src/components/screens/ | wc -l | grep -q '^0$'

# Count custom hooks following use-* naming convention
find apps/cli/src/hooks -name 'use-*.ts' -o -name 'use-*.tsx' | wc -l

# Verify React hooks usage in screen components
grep -r 'useState\|useEffect\|useCallback' apps/cli/src/components/screens/*.tsx | wc -l
```

**Accept when:**
- No class-based components exist in apps/cli/src/components/screens/ directory
- All custom hooks in apps/cli/src/hooks/ follow the 'use-*' naming convention
- Screen components demonstrate usage of React hooks (useState, useEffect, useCallback) for state management
- ESLint configuration includes react-hooks plugin with recommended rules enabled

<enforcement>
Claude Code MUST NOT skip or defer verification.

Verification is performed through:
- ESLint checks in CI pipeline with react-hooks plugin enabled
- Code review checklist verification of hook usage patterns
- Automated grep-based checks in pre-commit hooks to detect class components

Violation handling:
- CI build fails if ESLint detects hook rule violations
- PR reviews must address any class components introduced in screen directories
- Tech lead review required for any exceptions to the hooks-first approach

Exception process:
- Document the technical constraint requiring an exception in the PR description
- Obtain approval from tech lead or architecture review board
- Add inline comments explaining the exception and any planned migration path
- Track exceptions in technical debt backlog for future resolution
</enforcement>
