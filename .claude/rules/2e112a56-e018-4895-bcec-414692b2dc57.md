<rule_activation id="2e112a56-e018-4895-bcec-414692b2dc57" title="Adopt Playwright Browser Automation for E2E Testing and Demo Recording: Browser Automation Code" applies_to="**/*">
These rules apply to all browser automation code for E2E testing and demo recording.

**In scope:**
- All end-to-end testing that requires browser rendering
- Automated demo recording and screenshot generation for documentation
- Visual regression testing that validates UI rendering
- Integration tests that verify client-side JavaScript behavior

**Out of scope:**
- Unit tests that do not require DOM rendering
- API integration tests that do not involve browser UI
- Server-side rendering tests that can use simpler HTML parsing
- Performance benchmarks that use specialized profiling tools

**Exceptions:**
- EXC-001: Legacy tests using alternative frameworks (Selenium, Puppeteer) may remain during migration period
</rule_activation>

### Rules

- **R-PW-001** SHOULD: Browser automation code SHOULD be organized into reusable modules with clear separation between browser lifecycle management, locator resolution, and test/demo logic.

- **R-PW-002** SHOULD: Create a packages/browser module (or similar centralized location) that exports browser lifecycle management, locator resolution, and common test utilities.

- **R-PW-003** SHOULD: Implement resolve-locator utility with support for CSS selectors, XPath, text content, ARIA roles, and custom test ID attributes.

- **R-PW-004** SHOULD: Establish naming conventions for test IDs (e.g., data-testid attributes) following documented testing guidelines.

- **R-PW-005** SHOULD: Configure Playwright to run in headless mode in CI, headed mode for local debugging, with video recording on test failure.

- **R-PW-006** SHOULD: Use Playwright's built-in waiting mechanisms and retry logic to prevent flaky tests.

- **R-PW-007** SHOULD: New E2E tests SHOULD use Playwright and centralized locator utilities rather than alternative browser automation frameworks.

### Verify

```bash
# Check for Playwright dependency
grep -r "@playwright/test" package.json packages/*/package.json apps/*/package.json

# Check for centralized browser utilities
find . -name "*browser*.ts" -o -name "*locator*.ts" | grep -E "(packages/browser|utils)"

# Verify Playwright usage
grep -r "import.*playwright" --include="*.ts" --include="*.js" | wc -l
```

**Accept when:**
- Playwright is declared as a dependency in relevant package.json files
- Browser automation utilities exist in a centralized location (packages/browser or similar)
- At least one demo recording script or E2E test file imports and uses Playwright APIs
- New browser automation code uses the centralized locator resolution utilities
- Test IDs follow established naming conventions (data-testid attributes)

<enforcement>
Claude Code MUST verify Playwright usage and centralized browser automation patterns.

**Violation handling:**
- Pull requests introducing alternative browser automation frameworks (Selenium, Cypress, Puppeteer) should be flagged for architecture review
- Tests that bypass centralized locator resolution should be marked for refactoring
- Browser automation code outside approved packages should generate warnings

**Exception process:**
- Submit exception request with justification for alternative approach
- Document exception rationale in ADR amendments or inline code comments
- Set expiration date for temporary exceptions with migration plan
</enforcement>
