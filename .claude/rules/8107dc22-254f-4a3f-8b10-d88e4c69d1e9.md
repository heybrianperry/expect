<rule_activation id="8107dc22-254f-4a3f-8b10-d88e4c69d1e9" title="Standardize Core Utility Libraries for CLI and Browser Packages" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files in the codebase to ensure consistent utility library organization across CLI applications and browser packages.
</rule_activation>

### Rules

- **R-UTIL-001** MUST: All utility functions MUST be organized into dedicated modules within a utils/ directory structure.
- **R-UTIL-002** MUST: Shared utilities used across multiple packages MUST be extracted into the packages/ directory as reusable modules.
- **R-UTIL-003** MUST: Each utility module MUST have a single, well-defined responsibility (e.g., formatting, clipboard operations, image processing).
- **R-UTIL-004** SHOULD: State management utilities SHOULD be organized in a separate stores/ directory when using state management patterns.
- **R-UTIL-005** SHOULD: Utility modules SHOULD export pure functions without side effects where possible to improve testability.
- **R-UTIL-006** MUST_NOT: Utility modules MUST NOT contain business logic specific to individual features; they must remain generic and reusable.
- **R-UTIL-007** MAY: Application-specific utilities MAY remain in the application's utils/ directory if they are not needed by other packages.

### Scope

**In scope:**
- All utility functions in apps/cli/src/utils/
- All state management stores in apps/cli/src/stores/
- All shared libraries in packages/browser/src/ and packages/cookies/src/
- Client wrappers for external services (query-client, webdriver-client)
- Cross-cutting concerns like formatting, clipboard operations, and display management

**Out of scope:**
- Feature-specific business logic components
- UI components and presentation layer code
- API route handlers and backend services
- Configuration files and environment-specific settings
- Third-party library code not wrapped by internal utilities

### Verify

```bash
# Check utility file organization
find apps/cli/src/utils -type f -name '*.ts' | wc -l | grep -E '[0-9]+'

# Verify utility exports across apps and packages
grep -r 'export.*function' apps/cli/src/utils/ packages/*/src/ | grep -v 'node_modules'

# List shared package utilities
find packages/*/src -type f -name '*.ts' | head -5
```

**Accept when:**
- Utility functions are organized in dedicated utils/ directories within applications
- Shared utilities exist in packages/ directory and are imported by multiple applications
- Each utility module has a clear, single responsibility reflected in its filename
- No business logic specific to individual features exists in utility modules

<enforcement>
Verification MUST be performed during code review to ensure:
- Proper utility organization and single responsibility adherence
- No circular dependencies or improper imports
- Shared utilities in packages/ maintain semantic versioning and test coverage
- Utility modules remain cohesive and do not accumulate unrelated functions

Violation handling:
- Code review feedback requesting reorganization of misplaced utilities
- CI pipeline failures for circular dependency violations
- Refactoring tickets for utilities that have grown beyond single responsibility
- Documentation updates required for any exceptions to the standard pattern

Claude Code MUST NOT skip or defer verification.
</enforcement>
